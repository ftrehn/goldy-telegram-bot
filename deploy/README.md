# Выкладка

Бот, воркер, планировщик и сидер каталога — один образ и четыре команды. Собирается
он из корня репозитория, версию берёт из git, работает не от root. Всё, что отличает
боевой запуск от локального, живёт в `.env`; в самих файлах нет ни одного пароля по
умолчанию, и это намеренно: compose, поднимающийся с `guest/guest`, превращает
RabbitMQ на публичном адресе в чужую майнинг-ферму за сутки.

## Что нужно на сервере

Docker с плагином compose и больше ничего. Python, uv и just на сервере не нужны —
всё это остаётся в сборочной стадии образа.

## Первая установка

```sh
git clone <репозиторий> goldy && cd goldy
cp .env.example .env
# заполнить: TELEGRAM_BOT_TOKEN, POSTGRES_PASSWORD, RABBITMQ_USER, RABBITMQ_PASSWORD,
# GOLDY_DEFAULT_PRICE_TYPE_ID, GOLDY_ADMIN_PHONE_NUMBERS
docker compose up -d --build
```

Миграции накатываются отдельным одноразовым сервисом `migrate`, и три постоянных
процесса ждут его завершения. Запускать `alembic upgrade head` из точки входа бота
нельзя: три процесса на каждом рестарте гонялись бы за одним замком.

Каталог до появления обмена с 1С наполняется снимком:

```sh
docker compose run --rm bot python -m goldy.catalog_seed_app --file snapshot.json
```

## Обновление

```sh
git pull
docker compose up -d --build
```

Сервис `migrate` отработает заново и применит новые ревизии до того, как поднимутся
бот, воркер и планировщик. Простой равен времени пересоздания контейнеров.

## Что проверить после первого запуска

Логи `migrate` обязаны закончиться применённой ревизией, а не исключением. `docker
compose ps` показывает `bot`, `worker` и `scheduler` в состоянии `running`, а
`postgres`, `redis` и `rabbitmq` — `healthy`. В Telegram `/start` с телефона
администратора обязан выдать роль администратора: номера из
`GOLDY_ADMIN_PHONE_NUMBERS` применяются и при старте процесса, и при регистрации.

## Чего здесь сознательно нет

Обратного прокси и TLS: бот работает на long polling и сам ходит к Telegram, входящих
соединений у него нет. Публичный адрес понадобится только когда приедет обмен с 1С,
и тогда открывать надо будет приёмник обмена, а не бота.

Секретов в git: `.env` исключён и из репозитория, и из контекста сборки. На сервере
он создаётся руками один раз.

## Технические детали

- Образ: `python:3.14-slim`, две стадии, зависимости ставятся из `uv.lock` отдельным
  слоем и переживают правки кода.
- В сборочной стадии стоит `git` — `hatch-vcs` вызывает его, чтобы получить версию;
  в рантайм-образ он не попадает.
- Пользователь `goldy`, uid и gid 1000 — числовой, чтобы права на смонтированный том
  можно было сопоставить с хостом.
- Размер образа около 380 МБ.
- Тома: `postgres_data`, `redis_data`, `rabbitmq_data`.
- Порты наружу не публикуются ни одним сервисом.
