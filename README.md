# goldy

Бот интернет-магазина. Сейчас работает в Telegram, MAX запланирован. Каталог
товаров читается из 1С на отдельном сервере через RabbitMQ; покупатели и заказы
принадлежат самому боту.

Из 1С только читаем — никакой синхронизации обратно и никакого понятия
«контрагент» в домене нет.

## Ключевая идея модели

`User` — это **человек, а не аккаунт мессенджера**. Один и тот же человек,
пишущий из Telegram сегодня и из MAX завтра, — это один `User` с двумя
привязанными аккаунтами, одной историей заказов и одним номером телефона.

Опознаётся человек по номеру, поэтому номер обязателен с первой секунды и
берётся штатной кнопкой мессенджера, а не вводится руками. Почему именно так и
какие альтернативы отклонены — [ADR-0001](docs/adr/0001-single-user-across-messengers.md).

Термины: [CONTEXT.md](CONTEXT.md). Разбор модели пользователя:
[docs/design/user.md](docs/design/user.md).

## Архитектура

Чистая архитектура, слои проверяются линтером импортов:

```
src/goldy/
  domain/          бизнес-правила, ни от чего не зависят
  application/     сценарии, порты, пайплайны
  infrastructure/  адаптеры портов
  presentation/    Telegram: хендлеры, диалоги, middleware
  setup/           конфиги, bootstrap, DI-контейнеры
```

Зависимости направлены внутрь: `presentation → application → domain`.
`just import-linter` роняет сборку при нарушении.

Стек: Python 3.14, aiogram + aiogram-dialog, dishka, SQLAlchemy (императивный
маппинг) + PostgreSQL, taskiq поверх RabbitMQ, Redis, adaptix, Fluent для
текстов.

## Три процесса

| Процесс | Запуск | Делает |
|---|---|---|
| Бот | `python -m goldy.telegram_bot` | Принимает апдейты Telegram |
| Воркер | `taskiq worker goldy.worker_app:create_worker_taskiq_app` | Выполняет задачи, публикует события |
| Планировщик | `taskiq scheduler goldy.scheduler_app:create_scheduler_taskiq_app` | Дёргает релей outbox по расписанию |

У каждого процесса свой DI-контейнер поверх общего ядра. Это не украшение:
воркеру недоступен `IdentityProvider`, потому что фоновая задача — ничей запрос,
и контейнер откажется собраться, если сценарий, которому нужен актор, попадёт в
общий набор.

## Быстрый старт

Нужны Python 3.14, [uv](https://docs.astral.sh/uv/) и
[just](https://github.com/casey/just).

```sh
uv sync
cp .env.example .env      # заполнить токен и пароли
just migrate
python -m goldy.telegram_bot
```

`.env.example` перечисляет все переменные с комментариями. Значения по умолчанию
там закомментированы — раскомментировать нужно только то, что переопределяете.

## Переменные окружения

| Переменная | Обязательна | Что делает |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен от BotFather |
| `TELEGRAM_DEFAULT_LOCALE` | нет | Язык до того, как известен язык человека. По умолчанию `ru` |
| `TELEGRAM_USE_REDIS_STORAGE` | нет | Переживают ли диалоги рестарт. В проде — только `true` |
| `TELEGRAM_USE_REDIS_EVENT_ISOLATION` | нет | Обязательно `true`, если реплик больше одной |
| `POSTGRES_*` | да | `USER`, `PASSWORD`, `HOST`, `PORT`, `DB`, `DRIVER` |
| `DB_*` | да | Пул SQLAlchemy: `POOL_SIZE`, `POOL_RECYCLE`, `POOL_MAX_OVERFLOW`, `POOL_PRE_PING`, `ECHO` |
| `REDIS_*` | да | `HOST`, `PORT`, плюс четыре разные базы: `WORKER_DB`, `SCHEDULE_SOURCE_DB`, `CACHE_DB`, `FSM_DB` |
| `RABBITMQ_*` | да | `HOST`, `PORT`, `USER`, `PASSWORD`, `VHOST` |
| `TASKIQ_*` | нет | Имена очередей и политика ретраев |
| `GOLDY_ADMIN_PHONE_NUMBERS` | нет | Список номеров через запятую |

Четыре базы Redis — не перестраховка. Результаты задач, расписания, кеш и
состояние диалогов живут разное время, и `FLUSHDB` кеша не должен ронять всех
посреди оформления заказа. Загрузчик проверяет, что индексы различны.

### Первый администратор

Роль `ADMIN` нельзя выдать через бота никому: она выше всех в иерархии, поэтому
любая команда откажет. Первые администраторы задаются номерами:

```
GOLDY_ADMIN_PHONE_NUMBERS=+79991234567,+79997654321
```

Роль выдаётся и на старте процесса, и при регистрации, поэтому администратор
получит её независимо от того, зашёл он до деплоя или после. Номер, а не
`telegram_id` — иначе тот же человек, написавший из MAX, перестал бы быть
администратором.

## Команды бота

| Команда | Кому |
|---|---|
| `/start` | Всем. Единственное, что доступно незарегистрированному |
| `/help` | Зарегистрированным. Персоналу показывает больше |
| `/me` | Профиль: имя, язык, уведомления, отвязка мессенджера |
| `/admin` | Персоналу. Список пользователей, блокировки, роли |

## Разработка

```sh
just lint              # ruff format + ruff check + codespell
just mypy              # строгая типизация
just static-analysis   # mypy + bandit + semgrep + import-linter
just pre-commit-all    # всё, что гоняет CI
just test-unit         # быстрые тесты, Docker не нужен
just test-integration  # нужен Docker
just migration "текст" # новая ревизия alembic
just migrate           # применить
```

Перед коммитом должно быть зелёным `just pre-commit-all`.

## Состояние

Готово: домен пользователя, слой приложения (7 команд, 3 запроса),
персистентность, DI, регистрация, профиль и админка в Telegram, воркер и
планировщик, 202 юнит-теста.

Не сделано:

- **Каталог и заказы** — следующий большой кусок, вместе с чтением 1С.
- **MAX** — четвёртый контейнер поверх того же ядра, отличается только ответом
  на вопрос «кто пишет».
- **Тесты presentation.** Хендлеры, диалоги и middleware не покрыты ничем.
- **Миграция не проверена на живой базе.** Написана руками по DDL, собранному из
  метаданных; `just migration "check"` должен дать пустой диф.
