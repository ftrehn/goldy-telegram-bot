# goldy

Бот интернет-магазина. Сейчас работает в Telegram, MAX запланирован. Каталог
товаров — read-only проекция 1С; покупатели, корзины и заказы принадлежат самому
боту.

Из 1С только читаем — никакой синхронизации обратно и никакого понятия
«контрагент» в домене нет. Сам консьюмер 1С — следующий этап: пока проекция
наполняется вручную, JSON-снимком через сидер (раздел «Быстрый старт» ниже),
а порты и схема уже рассчитаны на то, что источник заменится на очередь RabbitMQ
без переделки домена.

## Ключевая идея модели

`User` — это **человек, а не аккаунт мессенджера**. Один и тот же человек,
пишущий из Telegram сегодня и из MAX завтра, — это один `User` с двумя
привязанными аккаунтами, одной историей заказов и одним номером телефона.

Опознаётся человек по номеру, поэтому номер обязателен с первой секунды и
берётся штатной кнопкой мессенджера, а не вводится руками. Почему именно так и
какие альтернативы отклонены — [ADR-0001](docs/adr/0001-single-user-across-messengers.md).

Термины: [CONTEXT.md](CONTEXT.md). Разбор модели пользователя:
[docs/design/user.md](docs/design/user.md).

## Архитектура

Чистая архитектура, слои проверяются линтером импортов:

```
src/goldy/
  domain/          бизнес-правила, ни от чего не зависят
  application/     сценарии, порты, пайплайны
  infrastructure/  адаптеры портов
  presentation/    Telegram: хендлеры, диалоги, middleware
  setup/           конфиги, bootstrap, DI-контейнеры
```

Зависимости направлены внутрь: `presentation → application → domain`.
`just import-linter` роняет сборку при нарушении.

Стек: Python 3.14, aiogram + aiogram-dialog, dishka, SQLAlchemy (императивный
маппинг) + PostgreSQL, taskiq поверх RabbitMQ, Redis, adaptix, Fluent для
текстов.

## Три процесса плюс сидер

| Процесс | Запуск | Делает |
|---|---|---|
| Бот | `python -m goldy.telegram_bot` | Принимает апдейты Telegram |
| Воркер | `taskiq worker goldy.worker_app:create_worker_taskiq_app` | Выполняет задачи, публикует события |
| Планировщик | `taskiq scheduler goldy.scheduler_app:create_scheduler_taskiq_app` | Дёргает релей outbox по расписанию |
| Сидер каталога | `python -m goldy.catalog_seed_app --file <снимок.json>` | Наполняет проекцию каталога из JSON-файла и завершается |

У каждого процесса свой DI-контейнер поверх общего ядра. Это не украшение:
воркеру недоступен `IdentityProvider`, потому что фоновая задача — ничей запрос,
и контейнер откажется собраться, если сценарий, которому нужен актор, попадёт в
общий набор. Сидер — четвёртая точка входа, а не флаг у бота: наполнение каталога
не должно быть тем, что умеет делать сам себе работающий бот, поэтому у него свой
контейнер, который не открывает брокер и не обслуживает никого — прочитал файл,
записал, вышел.

## Быстрый старт

Нужны Python 3.14, [uv](https://docs.astral.sh/uv/), [just](https://github.com/casey/just)
и Docker.

Начинаем с сервисов, а не с самого бота: боту нужны своя Postgres, Redis и
RabbitMQ, и `docker-compose.dev.yml` поднимает их локально, на смещённых
портах — 5434, 6380, 5673 — потому что 5432 и 5433 на машине автора уже заняты
PostgreSQL от 1С.

```sh
docker compose -f docker-compose.dev.yml up -d
uv sync
cp .env.dev.example .env      # порты уже настроены на docker-compose.dev.yml
just migrate
```

Каталог — read-only проекция, и без импорта он пуст: витрина откроется, но
показывать в ней будет нечего. Пока консьюмера 1С нет, наполняем сидером на
тестовом снимке из репозитория:

```sh
python -m goldy.catalog_seed_app --file docs/design/catalog-snapshot.example.json
```

Дальше — сам бот:

```sh
python -m goldy.telegram_bot
```

Она не заработает сама. Команда выше **не увидит** переменные, которые вы
только что записали в `.env`: код проекта читает окружение процесса при
старте, никакого dotenv-загрузчика в самом приложении нет, и «скопировать
файл» не означает «переменные из него попали в процесс». Файл `.env` без
дополнительного шага — просто файл на диске.

Единственное, что этот шаг сейчас делает сама по себе, — команды `just migration`,
`just migrate*`: заглянув в `justfile`, видно, что они идут через
`uv run --active dotenv -f .env run -- alembic ...`, то есть `.env` в окружение
подмешивает пакет `python-dotenv`, вызванный явно. У `python -m goldy.telegram_bot`,
`taskiq worker ...`, `taskiq scheduler ...` и сидера такой обёртки нет.

На Windows с PowerShell это делает `scripts\run-with-env.ps1`: он раскладывает
`.env` по переменным окружения текущего процесса PowerShell и запускает один из
процессов проекта.

```powershell
.\scripts\run-with-env.ps1 -Process bot -EnvFile .env
.\scripts\run-with-env.ps1 -Process worker -EnvFile .env
.\scripts\run-with-env.ps1 -Process scheduler -EnvFile .env
.\scripts\run-with-env.ps1 -Process seed -EnvFile .env -CatalogFile docs/design/catalog-snapshot.example.json
```

Выбор процесса по имени, а не приём произвольной командной строки, —
осознанное решение, а не недоделка: собственный разбор параметров PowerShell
перехватывает любой токен вида `-что-то` как попытку сопоставить его с
параметром скрипта раньше, чем тот дойдёт до вашей команды, и флаг вроде `-c`
у передаваемой программы можно молча принять за сокращение чужого параметра.
Закрытый список известных процессов эту ловушку убирает целиком.

`.ps1`-скрипт выполняется в том же процессе PowerShell, что и вызвавшая его
сессия — новую область видимости PowerShell даёт только переменным, а не
переменным окружения ОС, — поэтому вызванные им `SetEnvironmentVariable`
остаются в сессии и после того, как скрипт закончил работу: можно продолжать
работать в том же окне обычными командами.

На bash/zsh (Linux, macOS, WSL) готового скрипта нет, но задача решается одной
строкой без сторонних инструментов — так же, как это делает `justfile`, только
явно, без `dotenv`:

```sh
set -a; . ./.env; set +a
python -m goldy.telegram_bot
```

`.env.example` и `.env.dev.example` перечисляют все переменные с комментариями.
В `.env.example` значения по умолчанию закомментированы — раскомментировать
нужно только то, что переопределяете. `.env.dev.example` — готовый набор под
`docker-compose.dev.yml`, копируется как есть и требует только вписать токен
тестового бота.

## Переменные окружения

| Переменная | Обязательна | Что делает |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен от BotFather. Нужен всем трём процессам, а не только боту: воркер отправляет уведомления о заказах тем же ботом, а планировщик собирает брокер воркера, поэтому читает ту же переменную |
| `TELEGRAM_DEFAULT_LOCALE` | нет | Язык до того, как известен язык человека. По умолчанию `ru` |
| `TELEGRAM_USE_REDIS_STORAGE` | нет | Переживают ли диалоги рестарт. В проде — только `true` |
| `TELEGRAM_USE_REDIS_EVENT_ISOLATION` | нет | Обязательно `true`, если реплик больше одной |
| `POSTGRES_*` | да | `USER`, `PASSWORD`, `HOST`, `PORT`, `DB`, `DRIVER` |
| `DB_*` | да | Пул SQLAlchemy: `POOL_SIZE`, `POOL_RECYCLE`, `POOL_MAX_OVERFLOW`, `POOL_PRE_PING`, `ECHO` |
| `REDIS_*` | да | `HOST`, `PORT`, плюс четыре разные базы: `WORKER_DB`, `SCHEDULE_SOURCE_DB`, `CACHE_DB`, `FSM_DB` |
| `RABBITMQ_*` | да | `HOST`, `PORT`, `USER`, `PASSWORD`, `VHOST` |
| `TASKIQ_*` | нет | Имена очередей и политика ретраев |
| `GOLDY_ADMIN_PHONE_NUMBERS` | нет | Список номеров через запятую |
| `GOLDY_DEFAULT_PRICE_TYPE_ID` | да | Вид цен для покупателя без личной привязки. Обязателен: без него первому же такому покупателю ответили бы, что не настроен именно его прайс, хотя не настроен общий. Значение — идентификатор 1С вида цен, и он должен реально прийти в каталог импортом |

Четыре базы Redis — не перестраховка. Результаты задач, расписания, кеш и
состояние диалогов живут разное время, и `FLUSHDB` кеша не должен ронять всех
посреди оформления заказа. Загрузчик проверяет, что индексы различны.

### Первый администратор

Роль `ADMIN` нельзя выдать через бота никому: она выше всех в иерархии, поэтому
любая команда откажет. Первые администраторы задаются номерами:

```
GOLDY_ADMIN_PHONE_NUMBERS=+79991234567,+79997654321
```

Роль выдаётся и на старте процесса, и при регистрации, поэтому администратор
получит её независимо от того, зашёл он до деплоя или после. Номер, а не
`telegram_id` — иначе тот же человек, написавший из MAX, перестал бы быть
администратором.

## Команды бота

| Команда | Кому | Открывает |
|---|---|---|
| `/start` | Всем | Единственное, что доступно незарегистрированному — просит номер телефона |
| `/help` | Зарегистрированным | Список команд. Персоналу показывает больше |
| `/catalog` | Зарегистрированным | Каталог с дерева категорий |
| `/search <текст>` | Зарегистрированным | Поиск по каталогу. С аргументом, совпавшим ровно с одним товаром, открывает сразу его карточку |
| `/cart` | Зарегистрированным | Корзину — черновик заказа, общий для всех площадок человека |
| `/orders` | Зарегистрированным | Историю своих заказов |
| `/me` | Зарегистрированным | Профиль: имя, язык, уведомления, отвязка мессенджера |
| `/admin` | Персоналу | Список пользователей, блокировки, роли |
| `/manage_orders` | Персоналу | Очередь заказов на обработку |

Все команды, кроме `/start`, требуют регистрации и работают только в приватных
чатах. `/admin` и `/manage_orders` не показываются покупателю даже в подсказках —
`IsStaffFilter` на роутере молча делает их незаметными, а не запрещёнными: отказ
подтвердил бы, что команда существует.

## Разработка

```sh
just lint              # ruff format + ruff check + codespell
just mypy              # строгая типизация
just static-analysis   # mypy + bandit + semgrep + import-linter
just pre-commit-all    # всё, что гоняет CI
just test-unit         # быстрые тесты, Docker не нужен
just test-integration  # нужен Docker
just migration "текст" # новая ревизия alembic
just migrate           # применить
```

Перед коммитом должно быть зелёным `just pre-commit-all`.

## Состояние

Бот функционально дописан для одной площадки. Готово:

- **Домен.** Пользователи; каталог как read-only проекция без своего агрегата;
  корзина — агрегат `Cart`; заказ — агрегат `Order` со статусами, переходами
  между ними и спецификациями доступа к заказу.
- **Слой приложения.** 25 команд, 12 запросов, порты каталога, персональных
  цен, проекции, корзин, заказов и уведомлений, мапперы между доменом и
  view-моделями.
- **Персистентность.** 14 таблиц, императивный маппинг, `TypeDecorator`-ы и
  composite-типы под value objects, адаптеры всех портов, 5 ревизий Alembic,
  поиск по каталогу на `pg_trgm` и `tsvector`. Миграции прогнаны на реальной
  базе, а не только собраны из метаданных.
- **Уведомления.** Заказ размещён, статус сменился, адрес доставки исправлен —
  каждое из трёх доменных событий уходит через outbox в topic exchange
  `domain_events`, консьюмер FastStream в воркере читает свою очередь на
  событие и зовёт команду уведомления. Повторную доставку отбивает таблица
  `inbox_messages` по идентификатору сообщения, причём claim и отправка
  коммитятся одной транзакцией. Новый заказ уходит менеджерам и
  администраторам, смена статуса и правка адреса — покупателю, с уважением к
  его языку, выбранной площадке и блокировке. Тексты — собственный каталог
  Fluent в `ru`/`en`, отдельный от диалогов.
- **Presentation.** Семь диалогов aiogram-dialog — `admin`, `cart`, `catalog`,
  `checkout`, `manage_orders`, `orders`, `profile` — с локалями `ru`/`en`,
  плюс команды из таблицы выше. Три процесса и сидер каталога, все контейнеры
  dishka собираются.
- **Тесты.** 845 юнит-тестов, 205 интеграционных. Диалоги и хендлеры не остались
  без покрытия: интеграционные тесты гоняют их через замоканного бота
  (`tests/integration/telegram/`, `tests/integration/scenarios/`), а часть
  геттеров и виджетов покрыта юнитами напрямую
  (`tests/unit/presentation/telegram/`). Чего это покрытие не даёт — реального
  Telegram-клиента — закрывает ручной чек-лист:
  [docs/manual-check.md](docs/manual-check.md).
- **Ворота.** `ruff` чист, `mypy` чист по всем файлам src, `lint-imports` держит
  5 контрактов.

Сознательно не сделано — не потому что не успели, а потому что рановато или не
нужно прямо сейчас; полный разбор и причины каждого пункта —
[docs/design/ordering.md, раздел «Что сознательно не делаем сейчас»](docs/design/ordering.md#что-сознательно-не-делаем-сейчас):

- **Консьюмер 1С.** Каталог наполняется вручную, JSON-снимком через сидер.
  Порты и схема под будущий консьюмер уже стоят.
- **MAX.** Четвёртый контейнер поверх того же ядра, отличается только ответом
  на вопрос «кто пишет».
- Повтор заказа, правка состава размещённого заказа, платная доставка,
  назначение вида цен из бота, мультивалютная витрина.
